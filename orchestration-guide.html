Agent Orchestration Guide

Requirements → Code → Tests → Coverage Report, built by a pipeline of specialized Copilot agents

What this orchestration does

This workspace defines a multi-agent pipeline (agentic-orchestration-plan.md) that turns a raw customer requirements document into a working application with traceable, automated test coverage. A top-level Orchestrator agent never implements anything itself — it only delegates to specialist subagents (defined as .agent.md files under .github/agents) and gates progress on human approval wherever a decision could silently drift from what the customer actually asked for.

The pipeline is split into two flows:

Flow A — Initial build

Requirements doc → atomic, ID'd requirements → functional specs → code + tests generated in parallel per feature → traceability matrix → test execution → HTML report/dashboard.

Flow B — Requirement change loop

Updated requirements doc → diffed against the stored requirements → impact analysis flags affected code/tests in a review queue → human approves each item → only the affected requirement IDs are re-processed through Flow A.

See agent-hierarchy.html for a visual diagram of every agent in the pipeline, including which model tier each one runs on.

Running the orchestration on your own machine

1. Prerequisites

  1. VS Code with the GitHub Copilot and Copilot Chat extensions, signed in, with agent/subagent support enabled.
  2. Node.js (LTS) for the sample app, Playwright and the dev server (project1/serve.js).
  3. Python 3.x for the Robot Framework suite.
  4. Open this folder (SecretAgentTech) as a VS Code workspace, so .github/agents is picked up.

2. Kick off an initial build (Flow A)

  1. Open Copilot Chat in agent mode.
  2. Invoke the orchestrator, e.g. @Requirements-to-Tests Orchestrator (or ask to run it), and point it at a requirements document (e.g. project1/Määrittelydokumentti väripalvelusta.txt).
  3. The orchestrator delegates in sequence: Requirements Analyst → Functional Spec Writer → (Code Generation + Test Generation in parallel per feature) → Traceability Linker → Test Execution → Report Generation, logging cost via the Cost Estimation Agent after each step.
  4. Approve/clarify anything the orchestrator surfaces (ambiguous requirements, etc.) directly in the chat.
  5. When it finishes, it reports requirement/test/coverage counts and the paths to the generated HTML files.

3. Re-run after the requirements document changes (Flow B)

  1. Give the orchestrator the updated requirements document.
  2. It delegates to Change Detection → Impact Analysis, which writes review-queue.json.
  3. Review the queue with the orchestrator in chat and approve/reject each flagged item — nothing is rewritten silently.
  4. Approved items are re-processed through Flow A for just those requirement IDs, then Test Execution and Report Generation refresh the HTML outputs.

4. Manually running the generated app and tests (optional, no agents needed)

Useful if you just want to re-run what the agents already generated, from project1/:

cd project1
npm install

# serve the generated app (http://localhost:4173)
npm run dev

# Playwright tests + coverage -> coverage.lcov
npm test

# Robot Framework tests (needs: pip install -r tests/requirements.txt, then rfbrowser init once)
npm run test:robot

# merge Playwright + Robot results -> test-results.xml
npm run test:merge
Tip: project1/dashboard.html is the best starting point after any run — it links to the live app, the technical docs, and summarizes test/coverage/cost.
Note: This setup is for learning/experimentation. Human-review gates (ambiguous requirements, proposed test rewrites, deprecations) are intentional — don't configure the orchestrator to auto-approve them.
